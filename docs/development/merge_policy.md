# マージポリシー

## 原則

- `main` への直接 push は禁止する。
- `main` への変更は PR を必須とする。
- PR はレビュー完了後にのみマージ可能とする。

## 必須ステータスチェック

`main` へマージする PR には、次のチェック通過を必須とする。

- Workflow: `PR Quality Gate`（`.github/workflows/ci.yml`）
- Job: `lint`
- Job: `typecheck`
- Job: `test`

セキュリティ関連修正を含む PR でも同一の必須チェック（`lint/typecheck/test`）を適用する。

## 環境変数・シークレットのレビュー必須項目

- 環境変数 の追加/変更がある場合、Dev/Stg/Prod の接続先分離が説明されていることを 必須 とする。
- シークレット の追加/変更がある場合、GitHub/Vercel/Supabase の秘密管理に設定する手順が記載されていることを 必須 とする。
- `service_role` の利用範囲がサーバコンテキスト限定であることを明記する。
- Preview から Prod への接続経路を追加する変更は PRブロック 対象とする。

## セキュリティレビュー観点（必須）

- SQLインジェクション対策（パラメータ化クエリ）が維持されていること。
- XSS対策（HTMLエスケープ/サニタイズ）が維持されていること。
- 認証/認可の境界（RLS、特権鍵の利用範囲）が維持されていること。

## PRブロック条件

以下のいずれかに該当する場合は PRブロック とし、修正完了までマージ不可とする。

- 環境変数 の変更理由と適用環境（Dev/Stg/Prod）が不明。
- シークレット を平文でコミットしている、または秘密管理への移管手順がない。
- Preview から Prod へ到達し得る設定変更がある。
- 必須 ステータスチェック（`lint/typecheck/test`）が未通過。

## 例外運用

緊急対応時も原則PR経由とし、事後に必ずレビュー記録を残す。
