# REG-001 回帰テスト・自動化計画 テスト仕様書

## 1. テスト対象概要

- 対象要件:
  - Must機能回帰: `FR-001`〜`FR-017`, `FR-023`〜`FR-026`
  - 非機能回帰: `NFR-001`, `NFR-002`, `NFR-004`, `NFR-005`, `NFR-007`, `NFR-008`
  - 受入条件: `AC-001`〜`AC-017`, `AC-023`〜`AC-033`
- 対象設計: `SCR-001`〜`SCR-008`, `IF-001`〜`IF-005`, `BAT-003`, `BAT-004`
- 自動化ツール:
  - E2E: Playwright
  - API/DB回帰: HTTPテスト + SQL検証
  - 性能回帰: k6
- 方針: 手戻り影響が大きいフローを優先自動化し、手動セキュリティ/法令訓練は手動継続とする。

### 2.1 自動化対象選定基準
- 優先1: Must機能かつ障害影響が大きい（認証、認可、削除、監査）。
- 優先2: 回帰頻度が高い（習慣管理、チェックイン、設定）。
- 優先3: 判定を機械化しやすい（API応答、DB差分、ログ項目）。
- 非自動化: 手動判断が必要な法令訓練・体験品質評価。

### 2.2 スモークテスト定義
- 対象: `TC-AUTO-SMK-001`〜`TC-AUTO-SMK-005`
- 目的: PR段階で重大回帰を最短検知する。
- 実行時間目標: 10分以内。
- ブロック条件: 1件でもFailでマージ不可。

### 2.3 CI/CD連携方針
- PR作成時:
  - UT + `TC-AUTO-SMK-001`〜`005`
- `main` マージ時:
  - スモーク一式 + `TC-AUTO-REG-001`
- Nightly（毎日）:
  - `TC-AUTO-REG-002`, `TC-AUTO-REG-003`, `TC-AUTO-PERF-001`
- リリース候補（RC）:
  - 全自動回帰 + `TC-MANUAL-SEC-001` + `TC-MANUAL-APPI-001`

### 2.4 失敗時フロー
- PR失敗: マージ停止、担当者へ即時通知、修正後に再実行。
- Nightly失敗: 翌営業日朝会でトリアージし、P1/P2は当日修正。
- RC失敗: リリース判定を停止し、是正完了まで再判定不可。

### 2.5 運用品質KPI（自動化）
- 自動化カバレッジ（Must FRベース）: 80%以上。
- スモーク安定性（Flaky率）: 2%以下。
- 回帰検知リードタイム: PRから30分以内。
